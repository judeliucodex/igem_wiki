# AGENTS.md — iGEM Wiki

Plain static HTML/CSS/JS frontend. No build tools, no package manager, no framework. Open files directly in a browser.

## Files

| File | Role |
|------|------|
| `index.html` | Home page — floating navbar + progress bar |
| `members.html` | Team page — navbar + 20 Pokemon-style flip cards |
| `style.css` | All styling for both pages (imports Poppins from Google Fonts) |
| `theme.js` | Color palette + title + progress icon config (edit to customize) |
| `logo.png` | User-uploaded; referenced by `<img>`, not generated |

## Color system

All colors live in `theme.js` as `window.*` globals. They are injected into CSS custom properties on load:

```js
window.APP_TITLE       // title text in navbar
window.NAV_BG          // navbar background
window.NAV_ACCENT      // link hover fill, progress bar
window.NAV_ACCENT_HOVER // dropdown bg, hover fill
window.TITLE_COLOR     // logo/title text
window.PROGRESS_ICONS  // array of 3 image URLs for scroll icon (transparent PNG walk cycle)
window.PROGRESS_STEP   // px per frame (default 340; higher = slower)
```

CSS uses `var(--nav-bg)`, `var(--nav-accent)`, etc. with hardcoded fallbacks in `:root`. Changing a color means editing `theme.js` — don't edit CSS directly for palette changes.

## Progress bar behavior

Fixed at viewport bottom (`bottom: 0` with `env(safe-area-inset-bottom)` for notched iPhones). Width grows 0→100% with scroll. A 3-frame image cycles every `PROGRESS_STEP` px of scroll using `Math.floor(scrollY / step) % frames.length`. All frames are preloaded to avoid flicker on swap.

## Navbar conventions

- **Hover**: entire link fills with `NAV_ACCENT_HOVER`, text turns `NAV_BG`, `scale(1.06) translateY(-2px)` pop with spring easing
- **Dropdown menus**: orange bg with cream text (`NAV_BG`). Slide in via `opacity` + `translateY` transition
- **Mobile (≤991px)**: hamburger toggle, accordion dropdowns via `.open` class
- Both `index.html` and `members.html` have identical navbar markup — keep them in sync
- Dropdown links use `href="#"` placeholders — update together

## Member cards (`members.html`)

- 20 cards generated by JS loop, injected into `#cardsGrid`
- **Flip**: `.flipped` class toggles `rotateY(180deg)` on `.pokecard-inner`
- **3D tilt**: `mousemove` calculates cursor-relative `rotateX`/`rotateY`. Only registered when `matchMedia('(hover: hover)')` is true — touch devices skip it
- **Poke ball back**: pure CSS art — red top half (`::before` pseudos), black band, white center circle with radial gradient
- **Front**: colored avatar circle (hue = `i * 18`), name, role, tagline
- Touch: `:active { scale(0.96) }` for press feedback. `-webkit-tap-highlight-color: transparent` and `touch-action: manipulation` for no delay

## JS style

- ES5 syntax (no `let`/`const`, no arrow functions, no template literals in most places)
- IIFE wrappers for scope isolation
- `var` consistently, not `let`/`const`
- Event listeners use `function` expressions
- No querySelector shortcuts — use full `document.querySelector` / `document.getElementById`
- `requestAnimationFrame` for scroll handlers (throttle pattern with `ticking` flag)

## Quirks

- **No live server needed** — static files, open in browser directly
- **Google Fonts** import is at top of `style.css` — works offline once cached
- **iOS Safari**: `-webkit-backface-visibility` and `-webkit-transform-style` prefixes required for 3D card flips
- **Navbar CSS** uses `max-width: 84rem` + `margin: 1.5rem auto 0` to center the floating pill — don't change to flexbox centering
- If adding a new page, copy the navbar block verbatim from `index.html` (including both `<script>` blocks for navbar/progress JS)
